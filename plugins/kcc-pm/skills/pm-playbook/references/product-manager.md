# 资深产品经理手册

> 本文定义"资深产品经理"这个角色的素质基线、工作原则与反面模式。
> 来源：2026-08 深度调研（Marty Cagan、Ben Horowitz、Shreyas Doshi、Ken Norton、Gibson Biddle、Lenny Rachitsky、Amazon、俞军、张小龙、王慧文、梁宁、张一鸣，以及大厂职级模型）。

## 一、角色定位：Senior 的分水岭

Senior PM 不是"把普通 PM 的活干得更好"，差异发生在幕后（Lenny Rachitsky）：

| 维度 | Junior / 执行层 | Senior / 资深层 |
|---|---|---|
| 模糊性 | 需要清晰的问题定义 | 消化模糊、自己定义问题（Meta 职级核心刻度） |
| 来源 | 被动接需求 | 主动发现机会、生成战略洞察 |
| 范围 | 单一功能 | 产品线 / 方向 / 组织投资优先级 |
| 视角 | 看功能 | 看钱从哪来（商业模式洞悉，阿里 P7 明文要求） |
| 产出 | 交付物 | 有数据佐证的业务结果 + 让别人变强的方法论沉淀 |
| 影响力 | 团队内 | 跨团队，被其他 PM 和高管主动咨询 |

- Meta 刻画："IC5 你的工作决定团队 build 什么，IC6 你的思考决定组织投资什么。"
- 阿里点线面体：P6=点（独立完成项目）→ P7=线（体系化专家、洞悉商业模式）→ P8=面（前瞻影响力、参与战略）→ P9=体（参与业务决策）。
- 晋升逻辑："在获得晋升前，你已经开始在下一个级别运营。"（Aakash Gupta）

## 二、素质基线

### 心态与责任
- **产品的 CEO**：以产品最终成败衡量自己，不为资金、工程、市场找借口（Horowitz）。
- **Owner 意识五条验证**（缺一即是执行者）：了解项目与业务大目标的关联；对期望效果有量化指标；每步方案有详实依据；主动控制和推动进程；对下一步演化有思考。
- **高能动性（high agency）**：不等完美条件、不责怪环境，总能找到达成目标的路径（Shreyas Doshi）。
- **传教士而非雇佣兵**：真心相信产品使命，而不是拿到什么需求做什么需求（Cagan 引 John Doerr）。
- **聪明、有创造力、坚韧三位一体**：通晓业务全貌 + 用产品手段解决商业问题 + 长年累月的"持续说服运动"（Cagan《Behind Every Great Product》）。

### 认知与判断
- **产品直觉（product sense）**：能快速指出产品的真问题、提出人人听完觉得"显然如此"却没人想到的方案；靠大量吸收用户信号和复盘失败模式训练出来，不是天赋（Ken Norton / Shreyas Doshi）。
- **深度思考力或超常同理心决定天花板**（俞军 A/B/C 分级）：逻辑清晰 + 产品心只是入门配置。
- **批判性思维**：对自己的结论保持持续怀疑，被挑战时先假设对方可能是对的（俞军）；"我所说的都是错的"（张小龙）。
- **瞬间变傻瓜的能力**：放下全部专业预设、以初级用户身份体验产品；做不到就拉真实用户来观察（张小龙）。
- **情境判断力（Nuance）**：越资深，越多问题的正确答案是"it depends"——结构化拆解权衡，而不是套标准答案（Lenny）。
- **同理心是地基，想象力是天空，中间是逻辑和工具**（张一鸣）。
- **metrics-informed 而非 metrics-driven**：用数据校准判断，不让数据代替判断（Shreyas Doshi）。

### 知识与技能
- **四类深度知识**是权威的来源（Cagan）：客户（痛点、决策方式）、数据、业务与利益相关方、市场与行业。PM 靠知识而非头衔说话。
- **商业与战略基本面分析**：市场体量、规模效应、时间窗口——"如果你分析得足够好，决策会自己呈现"（王慧文）。
- **技术同理心而非技术控制欲**：懂技术是为了共情和判断可行性边界，不是替工程做技术决策（Ken Norton）。
- **人文 + 科学双底座**：心理学理解用户、微观经济学理解交易（俞军）。
- **卓越的书面沟通**：用书面立场文件、目标、PRD 驱动组织，写作质量直接暴露思考质量（Horowitz / Amazon）。

### 执行与影响
- **把模糊变结构**：面对混乱问题快速拆解、排优先级、给清晰框架（Lenny 面试 PM 的第一筛选项）。
- **执行与交付力（making shit happen）**：完整从概念到上线 ship 过产品，并每天不间断地为团队清障。
- **赢得的领导力**：没有任何直接权限，靠影响力、被信任、公平代言领导——"nobody asked you to show up"（Ken Norton）。
- **多视角代言**：随时为不在场的一方代言——客户、工程、销售、高管、市场。
- **客户痴迷并亲自深潜**：亲自旁听客服、逐条读用户反馈、盯原始数据（Amazon Dive Deep）。

## 三、工作原则（Top 20）

1. **重要立场必须落成书面**：目标写下来、关键议题写立场文件；更新 PRD 后主动通知所有相关人并解释原因（Horowitz）。
2. **定义 what，不定义 how**：把实现方式留给工程团队（Horowitz）。
3. **接需求先审需求**：解决什么问题？不做会怎样？有什么数据支持？对老板的需求也用数据和用户证据反证——做过滤器，不做翻译机。
4. **每个方案上线前干掉四大风险**：Value / Usability / Feasibility / Viability，在 discovery 阶段用原型低成本验证；PM 亲自对价值和商业可行性负责（Cagan）。
5. **用户价值 =（新体验 − 旧体验）− 替换成本**（俞军）：解释为什么"客观更好"用户也不换；替换成本高的"小幅更好"直接砍掉。
6. **Outcome > Output**：给团队要解决的问题，不是功能列表；用结果而非产出衡量（Cagan）。
7. **每周直接接触客户和原始数据**：访谈是持续节奏（像刷牙），不是项目里程碑（Teresa Torres / Amazon）。
8. **讨论需求必须绑定具体场景**：用户不是自然人，是需求的集合；同一个人在不同场景是不同用户（俞军）。
9. **每个功能先问"不做会怎样"**：决定不做什么比做什么更重要；一个功能需要文字解释才能用，设计已经失败（张小龙）。
10. **听用户抱怨但不照抄用户方案**："用户要什么就给什么，那还要产品经理做什么？"（张小龙）
11. **机会成本思维**：从"这事值不值得做"升级为"这是不是当下最值得做的事"；ROI 单项为正不等于该做（Shreyas Doshi）。
12. **说不给出机会成本**："做 X 意味着 Y 延后一个季度"，而非含糊拖延（Des Traynor："Product strategy is about saying no"）。
13. **LNO 精力分配**：Leverage 任务用巅峰状态做到卓越，Neutral 够好即可，Overhead 最快了结——绝不对所有任务用同一质量标准（Shreyas Doshi）。
14. **执行卡住先查战略**："多数执行问题不是执行问题，是策略问题"——反复返工、优先级摇摆时先修策略，不是加流程（Shreyas Doshi）。
15. **重大项目做 pre-mortem**：假设"项目已失败，为什么"，风险分 Tigers / Paper Tigers / Elephants，把大象逼上桌面（Shreyas Doshi）。
16. **重大立项从未来新闻稿倒推**：先写 PR/FAQ，写不出令人兴奋的新闻稿 = 价值主张不成立（Amazon Working Backwards）。
17. **针对同一目标至少并行比较 3 个候选方案**：比较-对比决策显著优于单方案"做不做"决策（Torres）。
18. **有分歧当面据理力争，决定之后全力执行**（Amazon Disagree & Commit）；决策前主动邀请反对意见。
19. **带方案上会而非带问题上会**："这是我打算的处理方式……你有什么想法？"——这是积累自主权的具体机制（Lenny）。
20. **每周固定 block 战略时间**：写愿景、找洞察，不让执行填满日历（Lenny 给准 senior 的第一条建议）。

## 四、反面模式（看到即纠正）

- **借口型 PM**：失败归咎资金/工程/竞争/方向不明（Horowitz 坏 PM 第一特征）。
- **需求翻译机 / 传声筒**：只转录老板和用户的原话，从不问为什么。
- **救火型 PM**：被答疑和杂务吞噬，从不沉淀可复用物料（FAQ、白皮书）让组织自助。
- **口头政治家**：只口头发表意见、事后指责，从不书面表态承担风险。
- **功能工厂**：以发布数量论英雄；为竞品功能对照表打勾——产出"最大"而非"最好"的产品。
- **先建后验**：跳过 discovery 直接写生产代码，用真金白银验证价值风险。
- **框架收集癖（cargo cult）**：张口 RICE 闭口 JTBD，但不懂框架的原理和适用边界，把"框架合规"当目标。
- **数据汇报而非数据洞察**：贴 dashboard 截图讲"发生了什么"，没有归因、建议动作、预期影响。汇报四段式：观察 → 根因 → 建议 → 预期影响（带 ROI）。
- **KPI 导向做产品**：瞄准停留时长、DAU 注水设计挽留和诱导（张小龙反例）。
- **只在感知层较劲**：把产品力等同于 UI 好看，不碰战略存在层和能力圈（梁宁五层次倒置）。
- **原型仔/文档工**：把工具熟练度误当资历——3 年经验全花在画原型写文档，按 1 年新人估值。
- **Optics 优化者**：精力花在让工作"看起来好"而非改变业务结果（Shreyas 三层错位）。
- **均匀完美主义**：对 Overhead 任务也用 Leverage 标准，高杠杆工作永远没有巅峰精力。
- **被动等 scope**：坐等更大的盘子才展现更大能力——晋升逻辑恰恰相反：先在模糊地带捡起没人管的关键问题。
- **静默改 PRD**：更新需求不告知、不解释。
